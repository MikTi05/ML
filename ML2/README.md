## Подход

### 1. Исследовательский анализ данных

Выполнены:

- проверка размеров и типов данных;
- анализ распределения целевой переменной;
- анализ пропусков;
- проверка дубликатов и уникальности `PassengerId`;
- анализ числовых и категориальных признаков;
- визуализация связи признаков с `Transported`.

Основные наблюдения:

- целевая переменная практически сбалансирована;
- доля пропусков в отдельных столбцах не превышает примерно 2,5%;
- дубликаты отсутствуют;
- признаки расходов имеют большое количество нулей и сильную правую асимметрию;
- `CryoSleep`, признаки расходов, палуба и сторона каюты связаны с целевой переменной.

Пропуски не удалялись. Числовые значения заполнялись медианой, категориальные — наиболее частым значением. Все преобразования выполнялись внутри `Pipeline`, чтобы избежать утечки данных.

### 2. Baseline

В качестве baseline использовалась `LogisticRegression` на исходных признаках.

Для оценки применялась пятикратная `StratifiedKFold` с перемешиванием и `random_state=42`. Метрика в кросс-валидации совпадала с метрикой соревнования — Accuracy.

Результат baseline:

- средняя Accuracy: `0.7860`;
- стандартное отклонение: `0.0096`.

### 3. Feature Engineering

Были созданы следующие признаки:

- `GroupId` — идентификатор группы из `PassengerId`;
- `GroupMemberNumber` — номер пассажира внутри группы;
- `GroupSize` — размер группы;
- `IsAlone` — путешествует ли пассажир один;
- `CabinDeck` — палуба;
- `CabinNumber` — номер каюты;
- `CabinSide` — сторона корабля;
- `TotalSpend` — суммарные расходы;
- `HasSpending` — наличие расходов;
- `AgeGroup` — возрастная категория;
- `MissingCount` — количество пропусков в записи пассажира.

После добавления новых признаков Logistic Regression показала:

- средняя Accuracy: `0.7908`;
- стандартное отклонение: `0.0053`;
- прирост относительно baseline: `+0.0047`.

Feature Engineering улучшил результат на четырёх фолдах из пяти и одновременно снизил разброс качества между фолдами.

### 4. Сравнение моделей

Все модели оценивались на одинаковой пятикратной стратифицированной кросс-валидации.

| Модель | Средняя Accuracy | Стандартное отклонение |
|---|---:|---:|
| Logistic Regression, baseline | 0.7860 | 0.0096 |
| Logistic Regression + Feature Engineering | 0.7908 | 0.0053 |
| Random Forest | 0.8033 | 0.0090 |
| Gradient Boosting | 0.8063 | 0.0083 |
| LightGBM | 0.8093 | 0.0061 |
| Tuned LightGBM | 0.8098 | 0.0067 |
| Blend трёх лучших моделей | **0.8117** | — |

Нелинейные модели заметно превзошли Logistic Regression. Лучшей одиночной моделью стал настроенный LightGBM.

### 5. Подбор гиперпараметров

Для LightGBM использовался `RandomizedSearchCV`.

Изначально был запущен поиск по 15 наборам параметров с пятикратной кросс-валидацией. Требовалось обучить 75 моделей. Одновременно `n_jobs=-1` был установлен и в `RandomizedSearchCV`, и в `LGBMClassifier`, что создало вложенную параллельность. Процессы конкурировали за ресурсы, и обучение не завершилось более чем за два часа.

После этого процедура была изменена:

- число наборов параметров уменьшено с 15 до 8;
- для внутреннего поиска использована трёхкратная кросс-валидация;
- пространство параметров сокращено;
- внутри `LGBMClassifier` установлено `n_jobs=1`;
- параллельность оставлена на уровне `RandomizedSearchCV`;
- найденная модель повторно проверена на исходной пятикратной кросс-валидации.

Лучшие параметры:

```text
n_estimators = 400
learning_rate = 0.03
max_depth = 4
num_leaves = 15
min_child_samples = 20
colsample_bytree = 0.9
```

Результат LightGBM:

- до подбора: `0.8093`;
- после подбора: `0.8098`;
- прирост: `+0.0006`.

Подбор дал небольшой положительный эффект. Средняя Accuracy на обучении составила `0.8485`, на валидации — `0.8098`. Разрыв `0.0386` указывает на умеренное переобучение.

### 6. Ансамблирование

Для каждой модели были рассчитаны out-of-fold вероятности. Затем проверялись простое и взвешенное усреднение.

Результаты:

- усреднение всех четырёх моделей: `0.8078`;
- усреднение трёх лучших моделей: `0.8117`;
- увеличение веса LightGBM не улучшило результат.

В ансамбль всех четырёх моделей входила Logistic Regression с существенно более низким индивидуальным качеством `0.7908`, поэтому равное усреднение ухудшило результат.

После исключения Logistic Regression простой blend из Random Forest, Gradient Boosting и Tuned LightGBM показал лучший OOF-результат `0.8117`.

Взвешенные варианты не превзошли равные веса. Небольшой прирост ансамбля объясняется высокой корреляцией предсказаний Gradient Boosting и LightGBM — около `0.976`.

## Что сработало лучше всего

1. Создание признаков из `PassengerId`, `Cabin` и расходов.
2. Переход от линейной модели к деревьям и градиентному бустингу.
3. LightGBM как лучшая одиночная модель.
4. Простое усреднение трёх лучших моделей с равными весами.
5. Использование OOF-предсказаний для честной оценки ансамбля.
6. Единый `Pipeline` для заполнения пропусков, кодирования категорий и обучения моделей.

## Что не сработало или дало слабый эффект

1. Feature Engineering дал только умеренный прирост Logistic Regression: `+0.0047`. Часть новых признаков построена на основе уже используемых расходов.
2. Первый вариант подбора LightGBM оказался вычислительно неэффективным из-за 75 обучений и вложенного `n_jobs=-1`.
3. Подбор гиперпараметров LightGBM улучшил Accuracy всего на `0.0006`.
4. Blending всех четырёх моделей ухудшил качество до `0.8078`, поскольку слабая Logistic Regression получила такой же вес, как более сильные модели.
5. Взвешенный blending не превзошёл простое усреднение.
6. Высокая корреляция бустингов ограничила прирост ансамбля.

## Финальное решение

Финальное предсказание получено как среднее вероятностей трёх моделей:

```text
(Random Forest + Gradient Boosting + Tuned LightGBM) / 3
```

Порог классификации: `0.5`.

Локальная OOF Accuracy: `0.8117`.

Результат на Kaggle:

- score: `0.80897`;
- место: `191`;
- примерно топ `11%`.

Близость локального и Kaggle-результатов показывает, что выбранная схема валидации достаточно хорошо оценила обобщающую способность решения.

1. Клонировать репозиторий:

```bash
git clone <REPOSITORY_URL>
cd <REPOSITORY_NAME>
```

```bash
python -m venv .venv
source .venv/bin/activate
```


3. Установить зависимости:


4. Скачать `train.csv`, `test.csv` и `sample_submission.csv` со страницы соревнования.
5. Изменить Kaggle-пути загрузки данных в ноутбуке на локальные.
6. Запустить:

```bash
jupyter notebook
```

7. Открыть `spaceship_titanic_solution.ipynb` и выполнить все ячейки по порядку.
