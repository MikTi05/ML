# Диагностика ИБС по медицинским показателям

Сравнение классических алгоритмов машинного обучения и нейронной сети (MLP)
на датасете UCI Heart Disease (Cleveland).

---

## Задача

Бинарная классификация наличия ишемической болезни сердца по 13 неинвазивным
и малоинвазивным показателям: анамнез, ЭКГ покоя, нагрузочный тест, биохимия крови.

Практический смысл — приоритизация пациентов для направления на коронарную
ангиографию, которая является инвазивной, дорогой и сопряжённой с риском процедурой.

**Ключевая особенность постановки:** цена ошибок несимметрична. Пропуск больного (FN)
несёт риск фатального исхода, ложная тревога (FP) — издержки на лишнее обследование.
Поэтому основной метрикой выбран ROC-AUC, а не accuracy, и отдельно подбирается
рабочий порог классификации.

## Данные

UCI ML Repository, `processed.cleveland.data`: 303 пациента, 13 признаков.
Целевая переменная (степень поражения коронарных артерий 0–4) бинаризована:
0 — здоров, 1–4 — есть ИБС. Распределение классов: 164 / 139 (54,1 % / 45,9 %).

## Методология

- Единая схема валидации для **всех** моделей: `StratifiedKFold(n_splits=5, shuffle=True)`
- Единая метрика: **ROC-AUC**
- Весь препроцессинг (импутация, масштабирование, one-hot) внутри `sklearn.Pipeline` —
  обучается заново на train-части каждого фолда, утечки нет
- Отложенный тест (61 пациент, 20 %) не участвовал в подборе гиперпараметров,
  отборе признаков и выборе порога — использован один раз, в самом конце
- **Вложенная кросс-валидация** для честной оценки процедуры подбора гиперпараметров

## Что сделано

| Раздел | Содержание |

| EDA | Распределения, корреляционная матрица, разрезы по классам; обработка пропусков и обоснованное решение по выбросам |
| Feature engineering | 5 признаков с клиническим обоснованием + ablation study их полезности |

| Нейронная сеть | MLP на PyTorch: обоснование архитектуры, кривые обучения, сравнение 5 схем регуляризации, исследование «глубина × ширина» |

| Прикладной анализ | Подбор порога под цену ошибок 10:1, error analysis, проверка по подгруппам |

Всего обучено и оценено **28 моделей**.

## Результаты

| Ранг | Модель | Семейство | CV ROC-AUC | Test ROC-AUC |
|---|---|---|---|---|
| 1 | LogReg (tuned, L1, C=1.52) | Линейные | **0.906 ± 0.021** | 0.957 |
| 2 | LogReg (L1) | Линейные | 0.906 ± 0.017 | 0.957 |
| 3 | LogReg (L2) | Линейные | 0.904 ± 0.024 | 0.961 |
| 4 | Stacking (LogReg) | Ансамбль | 0.903 ± 0.018 | 0.967 |
| 8 | MLP (PyTorch) | Нейросети | 0.892 ± 0.034 | 0.948 |
| 10 | RandomForest (tuned) | Ансамбли | 0.886 ± 0.027 | 0.978 |

### Основные выводы

**1. Простые регуляризованные модели не уступают бустингу и превосходят нейросеть.**
Первые три места заняли логистические регрессии. Средний overfit gap растёт строго
в порядке ёмкости моделей: линейные 0.027 → бэггинг 0.102 → нейросети 0.123 →
бустинг 0.124 → одиночное дерево 0.190. На 242 обучающих объектах ёмкость
сложных моделей не окупается.

**2. Различия между топ-моделями статистически незначимы.**
Парный t-тест по фолдам: 0 значимых различий из 15 пар. Медианный std по фолдам
(0.022) превышает разрыв между 1-м и 13-м местом рейтинга (0.014).

**3. Feature engineering не помог.**
Ablation study дал отрицательный результат для всех трёх семейств моделей
(LogReg 0.909 → 0.904, RF 0.888 → 0.867, GB 0.865 → 0.854). Из пяти
сконструированных признаков полезным оказался только `st_burden`, выражающий
мультипликативное взаимодействие. Для сравнения: отказ от признаков `ca` и `thal`
стоит 0.056 ROC-AUC — втрое больше.

**4. Ансамбли не превзошли лучшую одиночную модель.**
0 из 9 ансамблей выше по CV. Причина — средняя попарная корреляция предсказаний
базовых моделей 0.936: они ошибаются на одних и тех же пациентах. Выигрыш есть
только в калибровке (log-loss 0.256 против 0.282–0.294).

**5. Нельзя выбирать модель по тестовой выборке.**
У 27 моделей из 28 Test AUC выше, чем CV, а ранговая корреляция между оценками
всего **0.29**. `RandomForest (tuned)` — 15-е место по CV и 1-е по тесту.
На 61 объекте тестовая оценка имеет слишком большую дисперсию.

**6. Наибольший практический эффект дал не выбор алгоритма, а выбор порога.**
При соотношении цен ошибок FN:FP = 10:1 оптимальный порог смещается с 0.5 до 0.12,
что сокращает число пропущенных больных с 3 до 0 ценой роста ложных тревог с 5 до 17.
ROC-AUC при этом не меняется вовсе.

## Ограничения

- 303 пациента — доверительные интервалы всех метрик широки
- Данные одной клиники (Cleveland Clinic, 1980-е, преимущественно белое население США);
  вывод о переносимости на другие популяции сделать нельзя
- Признаки `ca` и `thal` получены дорогими процедурами; модель без них слабее
  на 0.056 ROC-AUC, но представляет отдельный сценарий применения (скрининг)
- Соотношение цен ошибок 10:1 — экспертная оценка, требует уточнения с клиницистами
